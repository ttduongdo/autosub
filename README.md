# AutoSub

A karaoke-style subtitle generator for music: give it a song, get back word-level synced lyrics, plus a from-scratch Whisper fine-tuning track aimed at improving transcription accuracy on sung vocals.

![status](https://img.shields.io/badge/status-active-brightgreen) ![python](https://img.shields.io/badge/python-3.11-blue)

## What it does

Paste a link or upload an audio/video file, and AutoSub:

1. Separates vocals from the instrumental (so the transcription model hears clean singing, not a full mix)
2. Transcribes the vocals with Whisper
3. Aligns the transcript to the audio at the **word level** — not just per-sentence, per-word — so lyrics can highlight in sync with playback, karaoke-style
4. Exports standard `.srt` / `.vtt` subtitles, plus the word-timing data the UI uses

It ships as a local web app: a waveform you can zoom/scroll, a synced lyrics strip beneath it, and a toggle between the full mix, vocals-only, and instrumental-only playback.

## Why this exists

Off-the-shelf ASR (including Whisper) is tuned for speech, and sung vocals are a genuinely different signal — pitch, sustain, backing instrumentation, and stylized pronunciation all throw it off in ways plain speech doesn't. This project tackles that gap from two directions:

- **Signal cleanup**: isolate vocals before transcription (Demucs) rather than asking Whisper to pick vocals out of a full mix itself.
- **Model adaptation**: fine-tune Whisper directly on sung lyrics, to see whether a small amount of music-specific training data measurably improves transcription accuracy over the baseline checkpoint.

## How it's built

**Pipeline** (`pipeline/`): ingest → Demucs vocal separation → Whisper transcription → forced alignment → subtitle export. The alignment step uses a CTC (wav2vec2) model to turn Whisper's sentence-level timestamps into true word-level timestamps — the part that actually makes karaoke highlighting possible.

**Web demo** (`app/`): a FastAPI backend with a hand-built frontend (not a pre-made UI toolkit) — a real waveform view with clickable, timestamp-synced lyrics underneath it.

**Fine-tuning** (`finetune/`): a LoRA fine-tuning track for Whisper, built around three pieces:
- A dataset builder that pulls recent, popular songs (Billboard Hot 100), gets real line-level timestamped lyrics from an independent lyrics database (not generated by the model being trained — avoiding the circularity of using Whisper's own output as training signal), and sources matching audio.
- A training script that LoRA-fine-tunes a Whisper checkpoint on short (~30s) chunks of timed lyrics, parameter-efficient enough to run on a single GPU.
- An evaluation script that measures word error rate (WER) for baseline vs. fine-tuned Whisper on a held-out set of songs, split by artist so no song/artist leaks between training and evaluation.

## Progress so far

The full pipeline and web demo are working end to end. The fine-tuning track has run several real training experiments at increasing dataset sizes, each evaluated with baseline-vs-fine-tuned WER on held-out songs.

**Honest status: fine-tuning hasn't beaten the baseline yet, on aggregate.** The most data-rich run so far had noticeably healthier training behavior (no longer badly overfit) than earlier, smaller runs, and shows real per-example transcription improvements on individual lines — but still comes out behind baseline in aggregate WER. The working theory is undertraining at the current experiment scale rather than a fundamental flaw in the approach, which points directly at the next step.

**Next up:** moving training off a laptop CPU/integrated-GPU setup onto real GPU compute, to make it cheap enough to iterate on epoch count and hyperparameters rather than treating every experiment as a multi-hour, one-shot run.

For context on what a mature version of this approach can achieve: a 2025 MSc thesis on Greek lyrics transcription ([Frangiadaki, Athena Research Center](https://arxiv.org/abs/2609.11302)) fine-tuned Whisper on sung lyrics and took zero-shot WER from 92% down to 30% — using more training epochs and GPU compute than this project has run so far. That gap lines up with the direction this project is already headed.

## Scope

This is a local, single-user project — no job queue, no database, no deployment. It's meant to demonstrate the full pipeline (classical audio processing + ASR + alignment) and a real, honestly-reported model fine-tuning experiment, not to be a production service.
